# Munder Difflin

ファビコンはクラリスの元スプライトを切り抜いた「ドット絵の顔アップ」案を採用。
`png/favicon_pixel_v1_16.png` と `png/favicon_pixel_v1_512.png` を使用する。元画像と比較候補は保管。

AIコーディングエージェント（Claude／Codex）とGPT画像生成を「AI社員」に見立て、
仮想オフィスで働く様子を眺めるツール。メイド版。

体制：画像＝リュミエール（GPT）／設計＝クラリス（Claude）／構築＝Codex。

## 動かし方

通常は、このフォルダの `起動.bat` をダブルクリックする。見回り役・HTTPサーバー・ブラウザが開く。
黒いウィンドウ2つは動作中は開いたままにする。閉じたあとは、もう一度 `起動.bat` で起動できる。
起動済み判定はstatusの更新時刻とポート番号による簡易判定。同時連打は避ける。

PowerShellでこのプロジェクトへ移動し、2つのターミナルでそれぞれ実行する。
Python 3.10以上が必要。外部パッケージは不要。

```powershell
cd "<このリポジトリを置いたフォルダ>"
python watcher.py --image-dir "<画像の出力フォルダ>"
```

```powershell
cd "<このリポジトリを置いたフォルダ>"
python -m http.server 8744 --bind 127.0.0.1
```

起動後、ブラウザで `http://localhost:8744/preview.html` を開く。
`file://` ではstatusの取得ができないため、必ずサーバー経由で開くこと。
停止は各ターミナルで `Ctrl+C`。

追加の画像出力先は次のように指定する。未指定でもプロジェクト直下を監視する。
画像フォルダは再帰探索せず、起動前からある画像は新規と数えない。

```powershell
python watcher.py --image-dir "<画像の出力フォルダ>"
```

`起動.bat` から使う場合は、このフォルダに **`image_dir.txt`** を作り、1行目にパスだけを書く。
ランチャーが読み取って `--image-dir` に渡す。ファイルが無ければ付けずに起動する。

```
C:\自分の画像出力フォルダ
```

このファイルは `.gitignore` 済み。**個人のフォルダパスを公開リポジトリに入れないための仕組み**なので、
スクリプトや説明書へ直接パスを書かないこと。

画面上部の「実測表示／デモ表示」で接続を見分ける。
60秒以内の活動は稼働中、60秒超〜30分未満は待機中、30分以上は退室中。
statusが欠損・破損・20秒超未更新ならデモへ戻り、回復すると実測表示へ復帰する。
デモ表示の理由は上部に表示する。「見回り役の更新が停止しています」ならwatcherのターミナル、「サーバーに接続できません」ならHTTPサーバーのターミナルを確認する。更新停止時には最終更新時刻と経過秒数も表示される。

## データの扱い

Claudeは `~/.claude/projects/` の各プロジェクト直下と指定フォルダ直下のjsonlを候補にする。
更新の新しい40セッションまでを監視する。`--claude-dir` で単一プロジェクトにも絞れ、
`--max-sessions 40` で上限を指定できる。上限超過時は `sources.claude: "limited"` と
`claudeScan`（found／selected／deferred／limit）を出し、画面にも上限ありと表示する。
リンク先や孫フォルダは探索しない。機密語を含む名前は除外する。

jsonlの会話本文は展開・表示・保存しない。構造を判別し、timestamp／tool_use.name／input.skillだけを取り出す。
初回は各セッションの末尾512KiBまでを読み、以降は前回読み終えた位置から続きを読む。
未完了の末尾行は次回に持ち越す。ファイルが差し替わった場合はアンカー照合で検知し、末尾512KiBから読み直す。
単一行が512KiBを超える場合や、1回のポーリング間に4MiBを超えて追記された場合は取りこぼすことがある。
初回のみ読み込みに数秒かかる（実測3秒前後）。以降の巡回は0.1秒未満。
CodexはDB内容を開かず更新時刻だけを使う。画像も内容を開かない。
データの外部送信は行わず、status.jsonはGit管理対象外。
監視元の未検出や読取エラーは画面上部と `status.json` の `sources` で確認できる。

## 動きと見分け方

稼働状態は見回り役のデータで決まり、歩行は演出。稼働中55%・待機中25%の確率で訪問を試み、退室中は席から動かない。
訪問先は左右1人ずつまで。満席ならその回は見送り、帰席・退室・表示モード変更時に枠を解放する。
OS／ブラウザの「動きを減らす」設定が有効なら全員が席に留まる。途中の設定変更にも追従し、状態と履歴は引き続き更新する。
退室中は65%の不透明度と控えめな彩度、灰色の名札で席を示す。稼働中は明るい名札と作業姿勢で区別する。

テストは合成データのみ使用。Nodeは開発用テストだけに使い、通常動作には不要。

最終的な受け入れ確認：

1. watcherとHTTPサーバーを起動し、画面が「実測表示」になることを確認。
2. マスターが別ターミナルで、指定のClaudeプロジェクトを使うClaude Codeにファイルの読み取り等を依頼。
3. 約4〜10秒以内にクラリスが「稼働中」になり、名札が点灯することを確認。
4. 最後のツール使用から60秒超で「待機中」、30分後に「退室中」（半透明）になることを確認。他セッションで同じ担当のツールを使うと時刻は更新される。
5. watcherを停止し、約20〜27秒後にデモへ戻ることを確認。

## 任意：ログオン時に見回り役だけを自動起動

自動登録は行っていない。必要な場合にユーザーがWindowsのタスクスケジューラで登録する。

1. 「基本タスクの作成」で名前を `Munder Difflin watcher` にする。
2. トリガーを「ログオン時」、操作を「プログラムの開始」にする。
3. プログラムに自分の `python.exe` のフルパスを指定する（`where python` で調べられる）。
4. 引数に `watcher.py` を指定する（画像フォルダは `image_dir.txt` で設定する）。
5. 開始場所にこのリポジトリのフォルダを指定する。
6. 作成後のプロパティで「ユーザーがログオンしているときのみ実行する」を選び、既に実行中なら「新しいインスタンスを開始しない」にする。管理者権限は不要。

見回り役だけが起動するので、オフィスを見るときは `起動.bat` を開く。
不要になったら当該タスクを「無効」にする。設定の登録・変更はユーザー自身が行う。
