# Munder Difflin

AIコーディングエージェント（Claude／Codex）とGPT画像生成を「AI社員」に見立て、
仮想オフィスで働く様子を眺めるツール。メイド版。

体制：画像＝リュミエール（GPT）／設計＝クラリス（Claude）／構築＝Codex。

- 設計の詳細は [`DESIGN.md`](./DESIGN.md) を参照
- `preview.html` — 9名の稼働表示。監視データがないときは訪問し合うデモ
- `watcher.py` — Claudeのツール・スキル、CodexのDB更新、画像出現を監視

## 動かし方

PowerShellでこのプロジェクトへ移動し、2つのターミナルでそれぞれ実行する。
Python 3.10以上が必要。外部パッケージは不要。

```powershell
python watcher.py
```

```powershell
python -m http.server 8744 --bind 127.0.0.1
```

起動後、ブラウザで `http://localhost:8744/preview.html` を開く。
`file://` ではstatusの取得ができないため、必ずサーバー経由で開くこと。
停止は各ターミナルで `Ctrl+C`。

追加の画像出力先は次のように指定する。未指定でもプロジェクト直下を監視する。
画像フォルダは再帰探索せず、起動前からある画像は新規と数えない。

```powershell
python watcher.py --image-dir "C:\実際の画像出力フォルダ"
```

画面上部の「実測表示／デモ表示」で接続を見分ける。
60秒以内の活動は稼働中、60秒超〜5分未満は待機中、5分以上は退室中。
statusが欠損・破損・20秒超未更新ならデモへ戻り、回復すると実測表示へ復帰する。
デモ表示の理由は上部に表示する。「見回り役の更新が停止しています」ならwatcherのターミナル、「サーバーに接続できません」ならHTTPサーバーのターミナルを確認する。更新停止時には最終更新時刻と経過秒数も表示される。

## データの扱い

jsonlの会話本文は展開・表示・保存しない。構造を判別し、timestamp／tool_use.name／input.skillだけを取り出す。
各セッションの末尾8KiBまでを読み、途中の行や未完了の行は除外する。
単一行や4秒間の追記が8KiBを超える場合、イベントを取りこぼすことがある。
CodexはDB内容を開かず更新時刻だけを使う。画像も内容を開かない。
データの外部送信は行わず、status.jsonはGit管理対象外。
監視元の未検出や読取エラーは画面上部と `status.json` の `sources` で確認できる。

## 検証

```powershell
python -m unittest -v test_watcher
node test_preview.cjs
```

テストは合成データのみ使用。Nodeは開発用テストだけに使い、通常動作には不要。

最終的な受け入れ確認：

1. watcherとHTTPサーバーを起動し、画面が「実測表示」になることを確認。
2. マスターが別ターミナルで、指定のClaudeプロジェクトを使うClaude Codeにファイルの読み取り等を依頼。
3. 約4〜10秒以内にクラリスが「稼働中」になり、名札が点灯することを確認。
4. 最後のツール使用から60秒超で「待機中」、5分後に「退室中」（半透明）になることを確認。他セッションで同じ担当のツールを使うと時刻は更新される。
5. watcherを停止し、約20〜27秒後にデモへ戻ることを確認。

2026-09-11：画面の自動テスト・Chromeでの合成データ表示確認は実施済み。
PythonテストはマスターのPowerShell（Python 3.13.15）で10件すべて合格（共有された実行結果：0.674秒、OK）。Codex側はPythonインストール先へのアクセスが拒否されるため、実行はマスター側で確認した。
実Claude Code操作後にクラリスが稼働中へ変わることをマスターが確認。提供スクリーンショットでもクラリスとコレットの稼働中表示・名札点灯を確認できた。フェーズ1の最重要条件である実連動確認は達成。
フェーズ2のブラウザ確認中、クラリスの待機→退室（半透明）を実時間でも確認済み。最後の活動14:59:26、15:04:43時点で退室中。時間境界の自動テストも合格。

背景は組み込み済み。キャラクターの座標を背景の机に合わせ、マスターの席は空席にした。画像が読み込めない場合は縞模様の床とCSSの机へ戻る。狭い画面ではオフィスを横スクロールできる。

## コマンドセンター

- ワーカー：9名の実測状態。キャラ画像や名前をクリックすると担当・部屋・状態の詳細カードが開く。
- タスク：検出したスキル名と呼び出し時刻。最大30件。jsonl全体の履歴ではなく、末尾で検知できた分を表示する。
- アクティビティ：プロジェクト直下と追加画像フォルダで起動後に新規作成・更新された成果物のファイル名と検出時刻。最大30件。本文は読み取らず、作業の成功や担当AIは推測しない。

履歴機能を反映するには、watcherをCtrl+Cで止めて `python watcher.py` を再実行し、ページを再読み込みする。HTTPサーバーはそのままでよい。
履歴はwatcher再起動でリセットされる。旧watcherのままでも稼働表示は継続するが、履歴欄に再起動の案内が表示される。

フェーズ3検証：Pythonはマスターの環境で12件合格（6.845秒、OK）。画面側自動テスト合格。Chromeで9名の状態表・キャラ詳細カード・実ファイルの更新履歴を確認済み。スキル履歴は合成データで検証済みで、実スキル呼び出しの表示は未確認。

コマンドセンターは右上のボタンで出し入れできます。Escキーでも閉じられます。キャラクターをクリックするとパネルが自動で開き、詳細を表示します。初期状態は閉じています。
